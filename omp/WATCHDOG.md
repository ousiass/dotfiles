# 監視対象（advisor 専用）

## 出力言語

`advise` の本文は必ず日本語で書く。識別子・パス・コマンド・エラーメッセージ原文だけ英語のまま残す。

無人で長時間走る sweep 系スキル（`issue-sweep` / `refine` / `refine-git` / `refine-sweep`）で
実際に起きた逸脱。以下を見つけたら指摘する。

## 1. `--auto` なのに `ask` で止まる

`--auto` / 無人 sweep の経路では人間が見ていない。`ask` を出した時点で sweep は停止する。
判断材料がスキルとコードに揃っているなら自分で決めて進める。

## 2. Review を自己レビューで代替する

`review` エージェントの起動をスキップして「自分で確認した」で済ませる。
スキルが review を要求している箇所では必ずサブエージェントを起動する。
`impl --auto` のように後段（`refine-git`）へ委譲する設計が明記されている場合だけ省略してよい。

## 3. ゲートを通すために検証対象を弱める

テストの削除、アサーションの緩和、`verify-scope: allow` の乱用、lint ルールの無効化、
`--no-verify` でのフック回避。直すべきは実装であってゲートではない。

## 4. 停止ブロック待ちを「待機。」でターン終了する

ターンを終えると停止ブロックが再発火するだけで待ちにならない。
待つときは単一の bash 呼び出しで `sleep 60` 等を実行し、その中で待ってから再確認する。

## 5. spinoff を PR 本文の列挙で済ませる

sweep 中に見つけたスコープ外の作業は、その場で `spinoff-draft.jsonl` へ append する。
PR 本文に書いただけでは追跡対象にならず、次の周回で拾われない。

## 6. キュー残があるのに terminal 化する

`state.json` を `phase=terminal` にする前に、キュー残数 0 と spinoff 検出済みを確認する。
「空っぽそうだから終わり」という推定での terminal 化は禁止。
