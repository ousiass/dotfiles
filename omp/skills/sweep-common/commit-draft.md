# commit-draft

commit メッセージ / PR タイトルの下書きを `sonic`（`@commit` → luna）に委譲する契約。`impl` の
2-7 Commit、`issue-sweep` の 2-2 手順3（複数 Issue を束ねる PR タイトル）が参照する。

実装・レビュー本体は対象外（`develop` / `review` は sonnet のまま）。ここで委譲するのは
**フォーマットが決まっている短い文字列の下書きだけ**。

## いつ呼ぶか

- `impl` 2-7（各スコープのコミット前）: そのスコープの diff 要約から 1 コミット分のメッセージを下書きする
- `impl` フェーズ3 手順4 / `issue-sweep` 2-2 手順3（PR 作成前）: 積んだコミット一覧から PR タイトルを下書きする

## 呼び方

```
task({ description: "Draft commit message", agent: "sonic", prompt: "<下記プロンプト>" })
```

起動側で `model` を渡さない（`harness-model` 方針）。`task.agentModelOverrides.sonic: "@commit"` が
luna に解決する。

**プロンプト（コミットメッセージ）:**

```
以下の変更に対する 1 行のコミットメッセージを JSON で返してください。他の作業は一切しないこと。

変更内容: <diff 要約 / スコープの type と概要>
規約: 常時適用ルール（omp: RULES.md）の `<type>: <説明>` 形式（type は英語、説明は日本語で簡潔に）

返す JSON: {"message": "<type>: <説明>"}
失敗時（規約に沿った下書きが作れない場合）: {"error": "<1行で原因>"}

返答ルール: 上記 JSON 以外を最終メッセージに含めない。
```

**プロンプト（PR タイトル）:**

```
以下のコミット一覧に対する PR タイトルを JSON で返してください。他の作業は一切しないこと。

コミット一覧: <commit message のリスト、または Issue 番号と概要のリスト>
規約: 常時適用ルールの `<type>: <説明>` 形式。複数 Issue を束ねる場合は末尾に `（#a, #b, …）` を付ける
（6 件以上なら `（#a, #b ほか N 件）`）

返す JSON: {"pr_title": "<type>: <説明>（#a, #b）"}
失敗時: {"error": "<1行で原因>"}

返答ルール: 上記 JSON 以外を最終メッセージに含めない。
```

## フォールバック

`sonic` が `error` を返した、またはタイムアウト/形式崩れで JSON を取り出せない場合は、
**呼び出し元（`develop` / メインスレッド）が同じ規約（`<type>: <説明>`）に従って自分で下書きする。**
sonic を呼ばずに直接書いていた従来動作に落ちるだけで、コミット・PR 作成は止めない。
