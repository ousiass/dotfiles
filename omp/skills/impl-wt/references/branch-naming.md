# ブランチ命名規則

## ブランチ名の決定

### ステップ1: ブランチ名を特定する

**Issue 本文にブランチ名が記載されている場合:**
- そのブランチ名を使用する

**記載がない場合は命名規則で決定する:**

| プレフィックス | 用途 |
|---|---|
| `feat/` | 新機能の追加 |
| `fix/` | バグ修正 |
| `refactor/` | リファクタリング |
| `docs/` | ドキュメントのみの変更 |
| `test/` | テストの追加・修正のみ |

判定に迷う場合は `feat/` をデフォルトとする。

- **Issue 指定時:** Issue のラベル・タイトルから type を判定し `<type>/#<Issue番号>` とする
  - ラベル `bug` → `fix/`、`enhancement`/`feature` → `feat/`
  - 例: `feat/#39`, `fix/#42`
- **テキスト / 引数なし:** 要件の内容から type を判定し `<type>/<要件を要約した短い名前>` とする
  - 例: `feat/add-auth`, `fix/login-error`

### ステップ2: 既存ブランチの確認（必須）

ブランチ名が決まったら、**worktree 作成前に必ず**リモートに同名ブランチが存在するか確認する:

```bash
git fetch origin
git branch -a --list "*<ブランチ名>"
```

- **存在する場合:** `git worktree add <パス> <ブランチ名>` で既存ブランチから worktree を作成する。新しいブランチは作成しない
- **存在しない場合:** `git worktree add -b <ブランチ名> <パス>` で新規ブランチの worktree を作成する

ベースブランチはスキル開始時のブランチとする。
