# review エージェント起動プロンプト

2-3 / 2-4 で `review` を呼ぶときは必ずこの形で渡す。差分だけ投げると、review が毎回文脈を自力で組み直したうえ、仕様書を見ないまま「要件適合」を判定してしまう。

```
以下の変更をレビューしてください。

## 要件（このスコープで満たすべきこと）
<Issue 本文の該当箇所、またはスコープ分割で決めた要件。原文のまま>

## スコープ境界
含む: <このスコープでやること>
含まない: <他スコープ・別 Issue に送ったこと。ここへの指摘は不要>

## 変更ファイル
<git diff --stat の出力>

## 仕様書の該当箇所
<spec_paths 配下で今回の要件に関係する記述。file:line 付き。無ければ「該当なし」>

## コンテキストパック
<references/context-pack.md で作ったパックをそのまま貼る>

## 重点的に見てほしい観点
<未実装チェック（モック/スタブのみ・TODO・空関数）は必ず含める>
<加えて、このスコープ固有のリスク（境界値・並行性・後方互換など）>
```

## 2 周目以降（指摘が再燃したとき）

上に加えて次の節を足す。これが無いと review は同じ指摘を出し直し、develop は同じ直し方を繰り返して 3 周の上限を食い潰す。

```
## 前回の指摘と対応結果
| 前回の指摘 | 取った対応 | 結果 |
|---|---|---|
| <指摘> | <どう直したか> | <解消 / 未解消: なぜ直せなかったか> |

未解消のものは「同じ直し方を繰り返さない」前提で、**別のアプローチ**を提案してください。
```
