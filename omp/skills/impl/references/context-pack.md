# コンテキストパック

実装前に**リポジトリ側の事実**を 1 回だけ集め、フェーズ2 の全サブエージェントに同じものを渡す。目的は「既存の類似実装を見落として車輪を再発明する」「その層の規約から外れた書き方をする」の 2 つを潰すこと。

## 作り方

**サブエージェントを立てず、impl 自身が Grep / Glob / Read で集める。** 探索結果はそのまま手元に残り、2-1 / 2-2 / 2-3 のプロンプトへ繰り返し埋め込むため、別 context に逃がす意味がない。

集め終えたら以下の**見出しを固定**して書く。各節は箇条書きで、**全体で 60 行以内**に収める。上限を超えるなら要件に近いものだけ残す（毎回すべてのサブエージェントのプロンプトに乗るので、量を増やすと逆効果になる）。

```markdown
## 類似実装
- <file:line> — <何をしているか。今回どう真似るか>

## この層の規約
- <エラー処理・命名・レイヤ分割・DI などの、実際のコードから読み取れた決まり>

## 触るファイル
- <path> — <追加|変更|削除。何を>

## テストの作法
- 配置: <path 規約>
- 書き方: <file:line を 1 つ挙げて「これに倣う」>
- 実行: <test_cmd>
```

## 集める順序

1. `spec_paths`（repo プロファイル）と Issue 本文から**ドメイン語彙**を拾う
2. その語彙で Grep し、**最も近い既存機能を 1〜2 個**特定する
3. その機能のファイル一式（実装・テスト・型定義・登録箇所）を読む
4. 3 で見た書き方を「規約」として言語化する。CLAUDE.md に明文の規約があればそれを優先する

## 書かないこと

- 一般的なプログラミング知識（サブエージェントは既に知っている）
- 要件そのものの言い換え（要件は別途プロンプトに入る）
- 「〜すべき」という規範（このパックは**観測した事実**だけを載せる。規範は SKILL.md と develop エージェントの責務）
