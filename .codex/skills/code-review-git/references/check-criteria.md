# コード品質チェック観点（差分対象）

| チェック項目 | 基準 |
|------------|------|
| **セキュリティ** | インジェクション、XSS、認証バイパス、シークレットのハードコード等がないか |
| **バグリスク** | nil/null 参照、未チェックの戻り値、型変換失敗、境界値未考慮、競合状態 |
| **エラーハンドリング** | 新規・変更箇所のエラーが適切に処理されているか |
| **ロジックの正確性** | 変更ロジックが意図通りか。エッジケースは考慮されているか |
| **パフォーマンス** | N+1 クエリ、不要ループ、メモリリークのリスク |
| **テスト** | 変更に対応するテストが追加・更新されているか |
| **命名・可読性** | 新しい変数名・関数名・クラス名が適切で一貫しているか |
| **重複コード** | 既存コードとの重複が発生していないか |
| **依存関係** | 新しい依存が妥当か。不要な依存がないか |
| **一貫性** | プロジェクトの既存パターン・規約に沿っているか |
| **Linterly 設定の改変** | `.linterly.yml` のデフォルト値（`max_lines_per_file: 300`, `max_lines_per_directory: 2000`, `warning_threshold: 10`）が緩和されていないか。`.linterlyignore` に不要な除外追加がないか。`lefthook.yml` から `linterly check` が削除されていないか |
