# 着手順序（正本）

画面をどの順で理解するか。**データ依存順のフェーズ**に従う。

## なぜこの順か

**依存の上流から学ぶと、後続画面に入る時点で「その概念はどこで定義済みか」を知っている状態になる。**

1画面ずつバラバラに学ぶと「この画面で完結している」と誤解し、別画面で担保済みのものを穴と誤認する。上流から順に積めば、その事故が構造的に起きない。

## フェーズ

**PJごとに埋める。** データの依存関係で並べる。上流＝他が参照する定義元、下流＝確定データを使う側。

> 例: 土台 → マスタ → トランザクション → 集計 → 出力 → 監査

## 運用

- **原則この順で進める。** 依存元が未学習の画面を先にやると、§7「この画面の外にあるもの」が埋まらない
- ユーザーが別の画面を指定したらそれに従う。ただし**依存元が未学習なら一言添える**
- フェーズ1は他の全画面の前提。ここは飛ばさない
- 学習済みの画面は `_概念の住所録.md` にエントリが増えていく。後のフェーズほど横断判定が速く正確になる
