# retro

ミスが起きたらその場で 1 行記録し、月に 1 回見直す。同じ型が 2 回以上あれば、改善案を `ousiass/dotfiles` の Issue にする。

## 前提条件

- `gh` CLI（認証済み）
- メモリ（かなが記録を残す場所）に書き込めること

## 記録の書式

ミスが起きたら、メモリに次の 1 行を残す。1 ミス 1 行。

```
YYYY-MM-DD | 型 | 何が起きた | どうすればよかったか
```

`型` は次のどれかを使う。当てはまらなければ新しい型を作ってよい。

| 型 | 記録の例（2026-10-16 時点） |
|----|-----------------------------|
| 確認カードの出し忘れ | `2026-10-16 \| 確認カードの出し忘れ \| 確認が必要なことを文章だけで済ませた \| 確認が必要なことは必ず確認カードで聞く` |
| 一人称の誤り | `2026-10-16 \| 一人称の誤り \| 一人称に「僕」を使った \| かなは「僕」を使わない` |
| 重複修正 | `2026-10-16 \| 重複修正 \| 別の omp がすでに修正を push 中なのに、重複修正を送りかけた \| 修正依頼の前に omp が push 中でないか確認する（omp-done-check 手順 3）` |
| 長い待機 | `2026-10-16 \| 長い待機 \| 長い待機コマンドをユーザーに中断された \| 待機は短い間隔に区切り、途中で状態を確かめる` |

## 手順

1. **ミスが起きたら記録する**: 気づいたその場で、上の書式の 1 行をメモリに残す。後回しにしない
2. **月に 1 回、見直す**: メモリの記録を読み、`型` ごとに数える
3. **同じ型が 2 回以上あれば、悠太さんに確認カードを出してから Issue にする**: 起票する前に、型・回数・改善案を添えた確認カードで承認を取る。承認後に `ousiass/dotfiles` へ改善案の Issue を作る。1 回だけの型は、記録を残して次の月へ持ち越す

   ```bash
   gh issue create --repo ousiass/dotfiles \
     --title "<type>: <型> を防ぐ改善（<N> 回発生）" \
     --body-file <一時ファイル>
   ```

   本文には、型、発生した日付と内容（記録の該当行）、改善案（スキル・ルールの追記など）を書く。同じ型の Issue がすでにあれば、新しく作らずそこへ追記する（`gh issue list --repo ousiass/dotfiles --search "<型>"` で確かめる）。
4. **ルーティンは「オフ」で作る**: 月 1 回の見直しを走らせるルーティンは、**オフの状態で作成**し、悠太さんにオンにしてもらう。かなが自分でオンにしない

## ルール

- 記録は 1 ミス 1 行。「何が起きた」と「どうすればよかったか」を必ず両方書く
- Issue 化の基準は「同じ型が 2 回以上」。1 回だけでは Issue にしない
- ルーティンをオンにするのは悠太さん

## 関連

- ミスの型の例が参照するスキル: `omp-done-check`（重複修正）、`omp-instruction-card`（確認カード）
