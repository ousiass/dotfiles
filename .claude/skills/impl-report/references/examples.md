# impl-report バリエーション例

宛先・目的・長さに応じた構成例。**内容は案件依存**（数値・仕様番号・PR/Issue番号は実際の作業に置き換える）。共通の作法は SKILL.md フェーズ4 の「可読性ルール」に従う（箇条書き主体・結論ファースト・1行1論点・各行は短く・括弧の入れ子禁止・冒頭は「○○を PR にあげました」だけ・状態や経緯は書かない・【参考】は書かない）。

## 1. 標準版（デフォルト・共有＋追認依頼）

```
お疲れさまです。勤怠一覧のステータスフィルタ（#227）を PR #234 にあげました。

【要確認】仕様にない判断
1. 複数フィルタ同時ON = AND（全条件を満たす行のみ）
2. 「未ロックのみ」= 日次・月次とも未ロック（§7.6 準拠）

【新規Issue】#233 無関係なツール警告を切り出し

1・2 をご確認ください。
```

## 2. 短縮版（要確認だけに絞る）

```
お疲れさまです。勤怠一覧のフィルタ（#227）を PR #234 にあげました。要確認2点:
・複数フィルタ同時ON = AND（全条件を満たす行のみ）
・「未ロックのみ」= 日次・月次とも未ロック（§7.6 準拠）
認識違いあればご指摘ください。
```

## 3. 共有のみ版（追認を求めない・事後報告）

```
お疲れさまです。勤怠一覧のステータスフィルタ（#227）を PR #234 にあげました。
・複数フィルタ同時ON = AND
・「未ロックのみ」= 日次・月次とも未ロック（§7.6 準拠）
・無関係なツール警告は #233 に切り出し済み
共有まで。
```

## 4. レビュー・承認依頼版（マージ前に担保を取る）

```
お疲れさまです。P-020 勤怠一覧フィルタ（#227）を PR #234 にあげました。マージ前にご確認ください。

【要確認】仕様にない判断
1. 複数フィルタ同時ON = AND（全条件を満たす行のみ）
2. 「未ロックのみ」= 日次・月次とも未ロック（§7.6 準拠）
3. 不正なフィルタ値はエラーで弾く（既存の年月指定に準拠）

問題なければそのままマージします。
```

## 5. 判断・報告事項が多い場合（全セクション）

```
お疲れさまです。○○（#NNN）を PR #MMM にあげました。

【要確認】仕様にない判断
1. ...
2. ...

【新規Issue】#XXX ...
【保留】... は未対応

特に1・2をご確認ください。
```

## 使い分けの目安

| 状況 | 使う版 |
|---|---|
| 標準（共有しつつ要所だけ追認） | 1. 標準版 |
| とにかく短く、要点だけ | 2. 短縮版 |
| 決定事項として流すだけ | 3. 共有のみ版 |
| マージ前に承認を取りたい | 4. 承認依頼版 |
| 判断・Issueが多い | 5. 全セクション版 |
