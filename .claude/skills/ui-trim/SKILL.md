# ui-trim

不要なボタン・重複した要素・使われない導線（冗長なUI）と、不要な説明文・重複した表現・長すぎる文言（冗長な文言）を検出し、削除・簡潔化・ヘルプ（モーダル等）への移動を提案して **Issue にする**。コードは変更しない。修正は Issue を渡して `/impl #<Issue番号>` で行う。

`design-review` とは別観点のため分けている（`design-review` は変更しない）。

## 前提条件

- Claude Code 環境
- `gh` CLI（GitHub Issue 出力時）

## 引数

- パス指定 (例: `/ui-trim src/pages/settings`): 指定されたファイル・ディレクトリのみ対象
- 引数なし: `AskUserQuestion` で対象を確認する

## フェーズ1: 対象と文脈の把握

1. 対象の画面・コンポーネントと使用フレームワークを把握する
2. 文言の管理方法を把握する（i18n ファイル、定数、直書き）
3. 既存のヘルプ表現（ヘルプモーダル、ツールチップ、折りたたみ、ヘルプページ）の有無と共通コンポーネントを検出する
4. 画面単位でタスク化する（TaskCreate）

## フェーズ2: 検出と提案

判定基準・提案の種類は `references/criteria.md` を参照。

- **冗長な UI**: 同じ操作の重複、遷移先のない導線、常に非表示/無効の要素、情報を足さない装飾
- **冗長な文言**: 見出し・ラベルの繰り返し、UI を見ればわかる説明、同義の重複表現、冗長な前置き
- **長い文言**: 常時表示するには長い補足・注意書き

提案は次のいずれか 1 つを付ける:

| 提案 | 使いどころ |
|------|-----------|
| 削除 | 外しても情報も操作も失われない |
| 簡潔化 | 意味は必要だが表現が冗長（簡潔化後の文言案を書く） |
| ヘルプへ移動 | 必要な人だけが読めばよい長めの説明（移動先と、ヘルプに入れる文言案を書く） |

各指摘に **根拠** を付ける（参照の検索結果・表示/到達条件・同一画面内の重複箇所）。根拠が取れないものは指摘しない。

## フェーズ3: 分類と確認

指摘を 3 つに分ける（確定条件は `references/criteria.md` の「確信度と分類」）:

| 分類 | 内容 | 扱い |
|------|------|------|
| 削除（確定） | 提案が削除で、確信度が高く、「外してはいけないもの」に当たらない | 確認せず Issue に入れる |
| UX 判断 | 簡潔化・ヘルプへ移動、確信度が中のもの | `AskUserQuestion` で確認してから Issue に入れる |
| 要判断 | 法務・課金・同意に関わるもの、意図が不明なもの | 確認せず「要判断」節に入れる |

UX 判断の確認:

1. 画面単位にまとめ、1 回 4 問までで聞く。選択肢は **採用（推奨・既定）/ 別案 / 見送り**。各項目の `description` に現状・変更後の案・根拠を書く
2. 採用は本文の「提案」に、別案は聞いた内容に直して「提案」に、見送りは Issue に入れない

## フェーズ4: Issue 作成

1. `AskUserQuestion` で出力先を確認する:
   - **GitHub Issue**（推奨）: タイトル `ui-trim: 冗長なUI・文言の削減(<ブランチ名>, <YYYY-MM-DD>)`
   - **ローカル MD ファイル**: `ui-trim-report.md`
2. 本文は `templates/report.md` に従う。`/impl` がそのまま実装できるよう、各項目に箇所・現状・提案・分類・変更後・根拠をそろえる
3. 作成した Issue の URL と件数（削除（確定）/ UX 判断で採用 / 見送り / 要判断）を報告し、「修正は `/impl #<Issue番号>`」と案内する

## ルール

- コードを変更しない。ブランチ作成・コミット・PR もしない
- 推測で指摘しない。コードを読み、参照を検索して裏付けを取る
- 指摘にはファイルパスと行番号を示す
- 入力欄のラベル・エラー文言・空状態の案内・破壊的操作の確認文は「冗長」として削除を提案しない（簡潔化・ヘルプ移動のみ可）
- 法務・課金・同意・セキュリティに関わる文言は、削除せず「要判断」に入れる
- ヘルプへ移動するとき、既存のヘルプ表現・共通コンポーネントがあればそれに合わせる。無ければ新設が必要と明記する
- 迷ったら削除（確定）にせず、UX 判断か要判断に回す
- TaskCreate/TaskUpdate で進捗を管理する
