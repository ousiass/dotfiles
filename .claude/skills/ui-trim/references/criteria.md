# 冗長判定の基準

## 冗長な UI

| パターン | 判定の目安 | 根拠の取り方 |
|---------|-----------|-------------|
| 重複する操作 | 同一画面に同じ結果の導線が複数ある（ヘッダーと本文に同じ「保存」、同じ遷移先のリンク/ボタン） | 同じ `onClick`/`href`/ルートを検索 |
| 使われない導線 | 遷移先のルートが存在しない、ハンドラが空、`href="#"` | ルート定義とハンドラ本体を確認 |
| 常に不可視/無効 | 条件が常に偽の `v-if`/`{cond && ...}`、フラグが常に false、常に `disabled` | フラグの定義・設定箇所を検索 |
| 情報を足さない要素 | 内容のないラッパー、同じ情報を繰り返す補助表示（タイトルと同内容のバッジ等） | 周辺要素との内容比較 |
| 過剰な確認 | 元に戻せる操作への確認ダイアログ、連続する同内容の確認 | 操作の可逆性（undo・ごみ箱の有無）を確認 |
| 重複する状態表示 | 同じ状態をアイコン・ラベル・トーストで同時に伝える | 表示条件の突き合わせ |

## 冗長な文言

| パターン | 例 | 提案 |
|---------|----|-------------|
| 見出し・ラベルの繰り返し | 見出し「設定」の下に「ここは設定画面です」 | 削除 |
| UI を見ればわかる説明 | ボタン「送信」の横に「クリックして送信します」 | 削除 |
| 同義の重複 | 「必ず必須の項目を入力してください」 | 簡潔化: 「必須項目を入力してください」 |
| 冗長な前置き・敬語の重ね | 「〜することができます」「〜していただけますようお願いいたします」 | 簡潔化: 「〜できます」「〜してください」 |
| 同一画面内の同じ注意書き | 各フィールドに同じ注意が並ぶ | 簡潔化: 1 か所にまとめ、残りは削除 |
| 内部事情の露出 | 実装・仕様の言い訳を述べる文言 | 削除 |
| 常時表示するには長い補足 | 入力欄の下に 2 文以上の使い方・注意書き。目安は 1 画面で 2 行を超える、または 80 字前後を超える説明（プロジェクトの慣習があればそれに従う） | ヘルプへ移動（ヘルプモーダル・ツールチップ・折りたたみ）し、画面には短い要約か「?」導線だけ残す |

## 外してはいけないもの

- フォームのラベル、`aria-label`、`alt`、`title`（支援技術が使う）
- エラー文言、バリデーション要件の説明（形式・文字数など利用者が知る手段が他にないもの）
- 空状態の案内、初回導線（オンボーディング）
- 破壊的操作（削除・退会・課金）の確認文
- 法務・規約・同意・個人情報の表記
- ヘルプへ移動する場合も、入力に必須の情報（形式・文字数・単位）は画面に残す

## 確信度と分類

| 確信度 | 条件 |
|-------|------|
| 高 | 参照・到達条件を検索で確認済み。外しても挙動・情報量が変わらない |
| 中 | 重複は確認できたが、どちらを残すかに判断が要る |
| 低 | 利用状況や意図が不明 → 要判断 |

削除（確定）にできるのは次をすべて満たすときだけ。1 つでも欠けたら UX 判断か要判断に回す。

- 確信度が高い（参照・到達条件を検索で確認済み）
- 提案が削除である（簡潔化・ヘルプ移動は常に UX 判断）
- 「外してはいけないもの」に当たらない
- 同一画面内の重複なら、残す側が明確（どちらを消すか判断が要るものは確信度が中）
