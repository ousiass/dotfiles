# 曖昧な回答への対応パターン

ユーザーの回答が曖昧な場合、以下のパターンで具体化する。
**選択肢を提示して選ばせる形式**を優先し、自由記述の負担を減らす。

## パターン一覧

| ユーザーの入力例 | 聞き出すべきこと | 選択肢の出し方 |
|---------------|---------------|-------------|
| 「いい感じに」「かっこよく」 | 方向性 | シンプル・クリーン / モダン・洗練 / 温かみ・親しみ / 力強い・インパクト |
| 「見やすくしたい」 | 何が見にくいか | 文字サイズ / コントラスト / レイアウト / 情報量 / 余白 |
| 「おまかせ」 | 判断基準 | プロジェクトの既存デザインから複数案を提示して選ばせる |
| 「普通でいい」 | 参考にする基準 | 業界標準パターンを2-3案提示 |
| 「統一感がない」 | 基準 | 既存の他の画面に合わせる / 新しい基準を定義する |
| 「シンプルに」 | 削る対象 | 装飾 / 情報量 / 操作ステップ / 色数 |
| 色の指定が曖昧 | 具体的なトーン | 既存パレットから選択肢 / 明るい系 / 暗い系 / パステル / ビビッド |
| レイアウトの指定が曖昧 | 配置 | 既存画面のパターンを選択肢で提示 |

## 原則

- 「おまかせ」と言われたら、プロジェクトのコードを調査してから複数案を提示する
- 既存デザイン基盤がある場合は、そこから選択肢を生成する
- 曖昧さの解消は最大2往復まで。それ以上かかる場合はベストプラクティスで提案する
