# カテゴリ別 Issue の形式

GitHub Issue に出すときは、上の全体レポートを使わず、指摘があるカテゴリごとに次の形で 1 件ずつ作る（C / T / S / I / M / O。親 Issue は作らない）。ローカル MD ファイル・PR コメントは上の全体レポートの形のまま。

```markdown
> 生成日時: YYYY-MM-DD HH:MM
> 対象プロジェクト: <プロジェクト名>
> チェック対象: <対象ファイル/ディレクトリ/PR/URL>
> 基準: Ousiass 共通デザインガイド（brand-guide `<コミット短縮 SHA>` / 公開ページ確認日 YYYY-MM-DD）
> 承認済みの逸脱: <docs の逸脱表の件数。無ければ「なし」>
> カテゴリ: <カテゴリ名>（<カテゴリ ID>）
> 全体の未確認: <公開ページ未確認など、カテゴリに紐づかないもの。無ければ「なし」>

## サマリー

| 重大度 | 件数 |
|-----|-----|
| 🔴 | N |
| 🟠 | N |
| 🟡 | N |
| 🟢 | N |

### 🔴 重大
（全体レポートの各カテゴリ節と同じ「ファイル / ガイドの定め / 問題 / 推奨」の形。🟠🟡🟢 も同様）

## ガイド未収載（追加提案）
このカテゴリに属するものだけ。無ければ節ごと省く。

## 未確認
このカテゴリの項目だけ。無ければ「なし」。
```

「ガイドのズレ」は Issue に入れず、チャットで報告する。
