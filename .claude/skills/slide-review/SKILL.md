# slide-review

既存の Slidev デッキをレビューし、指摘を1件ずつユーザーに確認しながら修正する。
`slide-gen` で作ったデッキにも、手で書いたデッキにも使える。

## 前提条件

- Claude Code 環境
- Bun（`bun --version`）
- PNG 出力に Chromium（`bunx playwright install chromium`）

## 引数

- 引数なし: `slide/` を自動検出してレビュー
- パス指定（例: `/slide-review slide/`）: そのディレクトリをレビュー
- モード指定: `はみ出し` `デザイン` `わかりやすさ` `構成` `規約` `すべて` のいずれか

## レビューモード

| モード | 内容 | 判定 |
| --- | --- | --- |
| **はみ出し** | 枠外へ出た要素をページ単位で検出 | 機械 |
| **デザイン** | 配色のコントラスト / 密度・強調・余白・ロゴ・視覚的階層 | 機械 + PNG 目視 |
| **わかりやすさ** | h2 の主張性、1ページ1主張、図と本文の重複、用語、数値の出典 | 本文 + PNG |
| **構成** | h2 の連なり、ゴール到達、dark の連続、パターンの連続、Appendix の使い分け | 本文 |
| **規約** | 色の直書き、画像による図解、ページ番号、独自クラスの乱造 | 本文 + CSS |
| **すべて** | 上記5モードを はみ出し → デザイン → わかりやすさ → 構成 → 規約 の順で実行 | |

観点の詳細は `references/check-criteria.md` を参照する。

## フェーズ1: 対象の検出と準備

### 1-1: デッキの探索

引数でパスが指定されていればそれを使う。無ければ Glob で探す。

```
**/slide/slides.md
**/slides/slides.md
**/slides.md
```

見つからなければユーザーにパスを確認する。

### 1-2: デッキの規約を把握

**レビューの基準はプロジェクト側にある。** 次を読んでから指摘を出す。

- `slides.md` と `src:` で読み込まれる全ファイル（**全文を Read**）
- `visual.css` の `:root`（配色トークン）と定義済みの `v-*` クラス一覧
- `README.md` の「デザインルール」「資料の構成」（あれば）

既存デッキが持つ規約に反する指摘をしない。例えば敬体で統一されたデッキに常体を勧めない。

### 1-3: ビルドと PNG 出力

```bash
cd <deck> && make install
make build   # 静的サイト（PDF は含まない）
make png     # public/<slug>/ に1ページ1枚。初回は Chromium を自動で入れる
```

`Makefile` が無いデッキでは直接叩く。

```bash
bun install && bun run build
bunx playwright install chromium
bunx slidev export --format png --output public/review --timeout 180000
```

### 1-4: モード選択

引数でモードが指定されていなければ `AskUserQuestion` で確認する。
選択肢の説明に、そのモードで何が見つかるかを書く。

対象ページ数が多い場合は、モードごとに `TaskCreate` でタスク化する。

## フェーズ2: レビュー実施

選択されたモードを順に実行する。`references/check-criteria.md` の観点で全ページを見る。

### はみ出し（機械）

```bash
make check                                     # Makefile があるデッキ
bun <skill>/scripts/check-overflow.mjs        # 直接叩く場合
bun <skill>/scripts/check-overflow.mjs --json # 機械処理する場合
```

ページ番号・はみ出し量・要素名が出る。終了コード 0 = 問題なし、1 = はみ出しあり。
`visual.css` は `overflow: hidden` なので、はみ出しは画面上では「切れて」見える。**目視だけで判断しない。**

### デザイン / わかりやすさ

配色は先に機械で測る。

```bash
bun <skill>/scripts/check-contrast.mjs        # visual.css の :root を実測
bun <skill>/scripts/check-contrast.mjs --json
```

本文 4.5:1・構造色 3:1 を下回る組み合わせを検出する。**NG は 🔴 として扱う。**

そのうえで、出力された PNG を**全ページ読む**。飛ばさない。ページごとに観点を当てる。
特に **`.accent` が付いたページでは、その強調に意味があるか**を必ず確認する
（並列に並ぶカードの最後というだけの強調は外す）。

### 構成 / 規約

本文（`slides.md` と Appendix）と `visual.css` を読んで判定する。

## フェーズ3: 指摘の確認と修正

指摘を**重大度順**に並べ、1件ずつ `AskUserQuestion` で確認する。

各指摘は次の形で提示する。

```
🔴 p12「4カテゴリの比較」
   表が下に 237px はみ出し、最終行が切れている
   → v-data-table-dense を併用し、列を4→3に減らす
```

選択肢は「修正する（推奨）」「このまま残す」「まとめて修正（以降の同種を自動適用）」。
**同種の指摘が5件以上あるときは1件ずつ聞かず、まとめて確認する。**

修正後は**必ずはみ出し検査を再実行する**（文言を削るとレイアウトが動き、別のページが崩れる）。
指摘なしになるまで繰り返す。上限3周。残った指摘はフェーズ4のレポートに残す。

## フェーズ4: レポート

修正が終わったら `AskUserQuestion` で出力先を確認する。

- **報告のみ**（推奨）: 修正内容と残課題を会話で報告する
- **ローカル MD ファイル**: `slide-review-report.md`
- **GitHub Issue**: タイトル `slide-review: スライド品質レポート(<デッキ名>, <YYYY-MM-DD>)`

レポート形式は `templates/report.md` を参照する。

## 同梱ファイル

| ファイル | 用途 |
| --- | --- |
| `references/check-criteria.md` | 5モードの観点と直し方（フェーズ2で読む） |
| `scripts/check-overflow.mjs` | 枠からのはみ出しを全ページ実寸で検査する |
| `scripts/check-contrast.mjs` | `visual.css` の `:root` からコントラスト比を実測する |
| `scripts/derive-palette.mjs` | 配色をやり直す場合に、プライマリ1色からトークンを導出する |
| `templates/report.md` | レポートの形式 |

## 重大度の基準

| 重大度 | 基準 | 例 |
| --- | --- | --- |
| 🔴 重大 | **読めない・見えない** | はみ出しで文字が切れる、dark 背景で文字が沈む、ページ番号が出ない、投影で読めない文字サイズ |
| 🟠 重要 | **主張が伝わらない** | h2 が見出し語で主張がない、1ページに主張が2つ、強調が複数箇所、図と本文が同じことを言っている、数値に出典がない |
| 🟡 提案 | **洗練度** | 情報の型に合わないパターン、同じパターンの3連続、`v-dark` の連続、密度の不均一 |
| 🟢 軽微 | **表記** | 用語の揺れ、桁区切りの不統一、英語ラベルと日本語ラベルの混在 |

🔴 と 🟠 は原則すべて修正する。🟡 🟢 はユーザーの判断に委ねる。

## 守ること

- **PNG を見ずにデザインとわかりやすさを判定しない**（本文だけでは崩れも密度もわからない）
- **はみ出しは機械検査で判定する**（目視では切れに気づけない）
- **プロジェクト固有の規約を優先する**（`visual.css` と README に書かれた方針に反する指摘をしない）
- **修正したら必ずはみ出し検査に戻る**。最後は検査が緑で終わる状態にする
- 指摘は必ず**具体的な直し方**とセットで出す（「読みにくい」だけで終わらせない）
- **強調に意味があるかを必ず見る。** `.accent` が並列の最後の1枚に付いているような
  装飾的な強調は外す。カードの色は区切りの構造であって情報ではない
