# チェック観点

各観点は「何を見るか」と「見つけたときの直し方」をセットで持つ。
直し方を示せない指摘は出さない。

## 1. はみ出し（機械）

`scripts/check-overflow.mjs` が全ページを実寸で開き、枠外に出た要素を検出する。

| 検出内容 | 重大度 | 直し方 |
| --- | --- | --- |
| カード列が枠外へ出る | 🔴 | `v-grid-compact` を併用、または項目を減らしてページを分ける |
| 表が下に溢れる | 🔴 | `v-data-table-dense`、それでも溢れるなら列を減らすか Appendix へ |
| 見出しが枠外へ回り込む | 🔴 | 文を短くする。`<br/>` で意味の切れ目に改行を入れる |
| 本文が入りきらない | 🔴 | 文字を縮めない。削るかページを分ける |

**文字サイズを縮めて収める提案は禁止。** 投影時に読めなくなる。

## 2. デザイン（PNG 目視）

| 観点 | 重大度 | 見つけ方 |
| --- | --- | --- |
| dark 背景で文字が沈む | 🔴 | dark ページの本文・注記が読めるか。`v-note-dark` の付け忘れが典型 |
| 投影で読めない文字 | 🔴 | 最小の文字が既存の注記サイズより小さくないか |
| ページ番号が出ていない | 🔴 | 表紙以外の全ページに `現在 / 総数` があるか |
| 強調が1ページに複数 | 🟠 | `.accent` カードが2枚以上、最強調色が同一ページに2箇所以上ないか |
| 密度がページ間で不均一 | 🟡 | 極端に空いたページと詰まったページが隣接していないか |
| 余白が不揃い | 🟡 | 同じパターンなのに上下の空きが違うページがないか |
| `v-dark` の連続 | 🟡 | dark が2枚続いていないか（章の句読点として使う） |
| 同じパターンの3連続 | 🟡 | 同一クラスのページが3枚続いていないか |
| 色数が多い | 🟡 | `:root` 以外の色が使われていないか（規約チェックと併せて見る） |

## 3. わかりやすさ

| 観点 | 重大度 | 判定 |
| --- | --- | --- |
| h2 に主張文が入っている | 🟠 | 「申請を出したあと、社員は待つ以外にできることがない」のような主張が h2 にある。h2 は**タイトル**（10〜20字）にし、主張は結論バナーかカードへ移す |
| h2 が長い / 2行になる | 🟠 | 20字を超えている。中身を名指しする短いタイトルに削る |
| h2 が何のページか示さない | 🟠 | 「〜について」「概要」など中身が読めない。「4つの手段の比較」のように名指しする |
| 主張がどこにもない | 🟠 | タイトルと図だけで、そのページで何が言いたいか読み取れない。`v-formula-banner` を最下部に足す |
| リード文が惰性で置かれている | 🟡 | `v-lead` が全ページにある。図より先に前提が要るページ以外は削る |
| 結論バナーと注記が併置 | 🟡 | `v-formula-banner` と `v-note` が同じページにある。どちらかにする |
| 1ページに主張が2つ | 🟠 | ページを分ける |
| 図と本文が同じことを言う | 🟠 | 図の下の注記が図の説明になっている。注記を消すか、図から導かれる結論に書き換える |
| 結論バナーが図の要約 | 🟠 | `v-formula-banner` は要約ではなく**そこから導かれる結論**を書く場所 |
| 数値に出典と年がない | 🟠 | 出典を添えるか、裏が取れないなら削って README の「未確定事項」へ |
| 用語が初出で未定義 | 🟠 | 略語・社内用語が説明なしに出ていないか。注記1行で足りる |
| 同じ概念を別語で呼ぶ | 🟢 | 資料内で語を1つに固定する |
| 箇条書きが長すぎる | 🟡 | 5行を超える、1行30字を超える |
| 修飾語が多い | 🟢 | 「非常に」「しっかりと」「きちんと」を削る |
| 桁区切り・単位の不統一 | 🟢 | 同じページ内で表記を揃える。比較する数値は基準年も揃える |

**タイトルで何のページか分かり、そのページの主張がどこかに1つある**ことが最終判定。

## 4. 構成

| 観点 | 重大度 | 判定 |
| --- | --- | --- |
| 主張を順に読んで接続が飛ぶ | 🟠 | ページが足りないか順序が違う。間を埋めるか並べ替える |
| ゴールに到達しない | 🟠 | 技術説明なら「この設計で作ってよい」、提案なら「話を先に進める」、報告なら「次に何を判断するか」に届いているか |
| 同じことを2回言っている | 🟠 | 片方を Appendix へ移すか削る |
| 章扉がない | 🟡 | Part の切り替わりに `v-dark` の扉が挟まっているか |
| 本編が長すぎる | 🟡 | 判断に要らないページを Appendix へ。本編 25〜35 ページが目安 |
| Appendix が余り物置きになっている | 🟡 | 質問されたときに開くページになっているか。番号（`Appendix B-7` 形式）で参照できるか |
| Appendix のページ番号が振り直されている | 🟠 | 本編からの通し番号にする |

## 5. 規約

| 観点 | 重大度 | 判定 |
| --- | --- | --- |
| 色が直書きされている | 🟠 | `slides.md` や `visual.css` の個別セレクタに `#xxxxxx` がある。`:root` のトークンに寄せる |
| 意匠がセレクタに直書き | 🟠 | 角丸・枠線・影・カードの地・見出しの太さが個別セレクタに書かれている。`:root` の意匠トークン（`--v-radius` `--v-card-*` `--v-h2-*` 等）へ寄せる |
| 図解が画像になっている | 🟠 | 構成図・フロー・比較・数値が PNG で貼られている。CSS のパターンで組み直す（差分レビューと文言修正のため） |
| 画像内に文字がある | 🟠 | 生成画像やスクリーンショットに文字が写り込んでいる。ラベルは HTML 側へ |
| 独自クラスの乱造 | 🟡 | 既存パターンの組み合わせで表現できるものに新クラスを作っていないか |
| `global-bottom.vue` がない | 🔴 | ページ番号が出ない。テンプレートから復元する |
| 存在しない画像を参照 | 🔴 | ビルドが `Module not found` で失敗する |

## 判定の順序

1. **はみ出し**を機械検査で潰す（他の指摘を直すとレイアウトが動くため、最後にもう一度回す）
2. **デザイン**と**わかりやすさ**を PNG で見る
3. **構成**を本文で見る
4. **規約**を本文と CSS で見る
5. 修正後、もう一度 1 に戻る
