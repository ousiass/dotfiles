# ousiass-design-guide

Ousiass 全プロダクト共通の UI デザインガイド（brand-guide）を、プロジェクトの仕様書・docs に**参照として**取り込み、準拠の土台を作る。ガイドの値を各プロダクトの docs に複製・再定義しない。

## 正と役割分担

- **正は brand-guide**: https://ousiassllc.github.io/brand-guide/ ・ リポジトリ `ousiassllc/brand-guide`。配布は npm / Go パッケージではなく、このスキルによる参照方式
- `references/brand-guide.md` は要約（取り込み時点のコミット付き）。食い違ったらガイドが正
- `design-spec`: 案件ごとの画面・コンポーネント・インタラクション仕様をヒアリングして作る。本スキルは、そこへ共通ブランドガイドを取り込む土台。Ousiass プロダクトの `docs/design/tokens.md` は `design-spec` で色・フォント・スペーシングをヒアリングせず、本スキルで埋める
- `ousiass-design-check`: 実装・PR・画面がガイドに沿っているかの確認。本スキルは書く側、あちらは確かめる側

## 前提条件

- Claude Code 環境
- ガイドの最新確認に Web 読み取り（`gh repo clone ousiassllc/brand-guide` でも可）

## 引数

- 引数なし: `AskUserQuestion` で対象（新規に取り込む / 既存の仕様書に追記）を確認する
- パス指定: そのドキュメントに参照を追記する

## 手順

### 1. ガイドの最新を確認

`references/brand-guide.md` の取り込み時点と、公開ページ（`tokens-preview.html`）の記載を突き合わせる。違いがあればガイドを優先し、完了報告に「要約のズレ」として書く。ガイドに載っていない値は書かない。

### 2. 既存ドキュメントの探索

`design-spec` の 1-0 と同じパターン（`**/spec*/**/*.md`, `**/docs/**/*.md`, `**/design/**/*.md`）で探し、読み込む。

- デザイントークンを扱う既存ファイルあり: そこへ「Ousiass デザインガイド準拠」節を追記する（既存の構造・スタイルを優先）
- なし: `docs/design/ousiass-design-guide.md` を新規作成する（`design-spec` の標準配置 `docs/design/` に合わせる）
- 既存の独自トークン（色・フォント・スペーシング）がガイドと食い違う場合: 勝手に書き換えず、`AskUserQuestion` で「ガイドに合わせる / 逸脱として残す」を確認する

### 3. 書く

`templates/spec-section.md` に従い、次を書く:

1. **準拠宣言と正の参照**: ガイドの URL と参照した時点
2. **トークン参照表**: 使うトークンを**名前**で参照する（`--ink` `--s-4` `--r-md` `--motion-fade-in` など）。hex・px の値は書かない（実装は共通トークンを取り込む）。値が必要な読み手のためにガイドへのリンクを置く
3. **採用する部品**: ガイドにある部品名（例: P1「ページネーション」、P2「コーチマーク」）で列挙し、画面仕様からはその名前で参照する
4. **案件固有部品**: P3 の独自ウィジェットなど、ガイドにないもの。「案件ガイドで定義」と明記し、共通ガイドへの追加提案が要るものは「ガイド未収載・追加提案」として保留にする
5. **逸脱**: ガイドから外れる箇所は逸脱表に理由と承認者を書く（無ければ「なし」）

### 4. 画面仕様との接続（`design-spec` の各ドキュメントがある場合）

| docs | 書き方 |
|---|---|
| `components.md` | 部品は**ガイドの部品名**で参照。ガイドにない部品を足さない |
| `interactions.md` | モーションはガイドのトークン（`--motion-*`）と Do/Don't の範囲。reduced-motion の挙動を書く |
| `screens.md` | 余白は間隔レシピのトークン名で指定。オーバーレイは中央モーダルが基本、外側クリックで閉じる |

### 5. 確認とコミット

ユーザーに提示して確認し、`CLAUDE.md` のコミット規約に従う。

## ガイドの要点（書くときに外さない）

- 色: UI はほぼ無彩色。プリズム（violet→yellow）はロゴ・キービジュアル専用で、ボタン・リンク・フォーム・チャートには使わない。フォーカスリングだけ `--focus`（青）。コーチマークは `--ink` グレーのパルスで、focus 青は使わない
- タイポ: Sora + Noto Sans JP、コードは JetBrains Mono。サイズはスケール（12/14/16/18/24/32/40）から選ぶ。SemiBold は見出しとボタンだけ
- アイコン: Iconoir（16 / 20 / 24。empty state のみ 32 可）
- 優先度: P0 骨格 / P1 部品 / P2 上級 / P3 メディア・エディタ。どれもガイドにあるものだけ使う
- モーション: 静かだけど動きがある。静か・短く・目的があるときだけ。reduced-motion 対応
- オーバーレイ: 中央モーダルが基本。共有などはボトムシート可。外側（スクラム）クリックで閉じる

詳細は `references/brand-guide.md`。

## ルール

- ガイドにない部品・値・モーションを仕様に書かない。必要なら「ガイド未収載・追加提案」として保留し、ガイドの更新を先に提案する
- 値を再定義しない。トークン名で参照する
- ライト / ダークの両方を前提に書く（片方だけの記述をしない）
- 既存ファイルの更新は `Edit` で直接行う。同じ内容の新規ファイルを別の場所に作らない
- 不明点は推測せず `AskUserQuestion` で選択式に確認する
- ドキュメントを更新したら、そのファイルの改訂履歴に追記する（既存フォーマットに合わせる）
