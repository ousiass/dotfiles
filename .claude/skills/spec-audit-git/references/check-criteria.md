# 検知観点と重大度基準（差分版）

## 検知カテゴリ

すべて **差分に起因するもののみ** が対象。

| カテゴリ | 検知内容 | 検索手段 |
|---------|---------|---------|
| **差分コード vs 仕様書** | 差分で変更された機能・エンドポイント・振る舞いが関連仕様書と一致するか | Grep / Read |
| **仕様書変更 vs 実装** | 差分の仕様書変更に対応する実装が差分にあるか | Grep / Glob |
| **TODO/FIXME** | 差分で**追加された** `TODO`, `FIXME`, `HACK`, `XXX`, `TEMP` | `git diff` の `+` 行 |
| **スキップテスト** | 差分で**追加・skip 化された**テスト | `git diff` の `+` 行 |
| **API スキーマ** | 差分の OpenAPI/Swagger 変更に対応するハンドラが差分にあるか | Grep / Glob |
| **設定・環境変数** | 差分で追加された設定項目が仕様書に記載されているか | Grep |
| **データモデル** | 差分のマイグレーション/モデル変更が ER 図・テーブル定義と一致するか | Grep / Read |

## スキップテストの検索パターン

| 言語 | パターン |
|------|---------|
| JS/TS | `it.skip`, `describe.skip`, `test.skip`, `xit`, `xdescribe`, `xtest` |
| Go | `t.Skip` |
| Python | `@pytest.mark.skip`, `@unittest.skip`, `self.skipTest`, `pytest.skip()` |
| Ruby | `skip`, `pending` |
| Java | `@Disabled`, `@Ignore` |
| Rust | `#[ignore]` |

## TODO マーカーパターン

`TODO`, `FIXME`, `HACK`, `XXX`, `TEMP`, `WORKAROUND`

## 重大度基準

| 重大度 | 基準 | Issue 作成 |
|-------|------|-----------|
| 🔴 重大 | 差分の仕様書変更に対応する実装がない、スキーマに追加したエンドポイントにハンドラがない、差分の実装が仕様書と明確に矛盾 | 必須 |
| 🟠 重要 | 差分の実装が仕様の一部のみ充足、FIXME/HACK で仮実装、既存テストを差分で skip 化、API/設定変更に仕様書が未追随 | 必須 |
| 🟡 注意 | 差分で TODO コメントを追加、仕様と差分に軽微な差異 | 推奨 |
| 🟢 軽微 | デフォルト値の差異、表記ゆれ | 任意 |

## 対象外

- 差分に含まれないファイルの TODO/FIXME・スキップテスト
- 差分と無関係な仕様書記述の未実装（`spec-audit` の担当）
- コード内のコメント・docstring の文言（`doc-drift-git` の担当外でもあるが本スキルでも扱わない）
