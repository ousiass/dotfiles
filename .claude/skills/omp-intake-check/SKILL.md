# omp-intake-check

ほかのボット（あおい・るな・なな）から来た omp 依頼を、omp に入れる前に確かめる。足りないものがあれば、悠太さんへ丸投げせず、まず依頼元のボットへ差し戻す。

## 前提条件

- `gh` CLI（認証済み）
- 依頼の全文が手元にあること

## 手順

次の 5 項目を順に確かめる。1 つでも引っかかったら、その項目の対応を取り、omp には送らない。

1. **決まっていない判断が残っていないか**
   - 「どちらでもよい」「必要なら」「適宜」など、判断を omp に委ねている箇所を探す
   - 残っていれば、悠太さんへ丸投げせず、依頼元のボットに差し戻して決めてもらう（下記「差し戻し文面のひな形」を使う）
2. **すでに実装済みでないか**
   - コード・Issue・PR を確かめる

     ```bash
     gh issue list --state all --search "<キーワード>"
     gh pr list --state all --search "<キーワード>"
     git log --oneline --grep "<キーワード>"
     ```

   - 実装済み・進行中のものがあれば、その旨を依頼元に伝えて依頼を取り下げてもらう
3. **承認済みの範囲を超える追加依頼になっていないか**
   - 悠太さんが承認した範囲と突き合わせる。超えるなら、悠太さんに確認カードで確認する
4. **作業場所が決まっているか**
   - リポジトリ、worktree、ブランチ
   - 触ってはいけない場所（ほかの omp が作業中の worktree、`main` など）
5. **欲しい証拠が明記されているか**
   - テスト結果、CI、スクショなど、完了報告に何を付けてほしいか

すべて問題なければ、`omp-instruction-card` の手順で omp へ送る。

## 差し戻し文面のひな形

依頼元のボット（あおい・るな・なな）宛て。決めてほしい点を箇条書きにする。

```
<依頼元ボット名> さん

omp への依頼を確認しました。次の点が決まっていないので、決めてから送り直してください。

決めてほしい点:
- <判断が残っている点 1（選択肢があれば併記）>
- <判断が残っている点 2>
- <作業場所（リポジトリ / worktree / ブランチ）、触ってはいけない場所>
- <欲しい証拠（テスト結果 / CI / スクショ）>

すでに実装済みの可能性があるもの:
- <Issue / PR 番号と、重なる点>

決まったら、全文を添えて送り直してください。
```

該当しない行は削る。

## ルール

- 決まっていない判断を、悠太さんへ丸投げしない。まず依頼元に決めてもらう
- 承認済みの範囲を超える追加は、依頼元が決めることではなく、悠太さんに確認する
- 依頼の中身を、確認なしで足したり変えたりして送らない
