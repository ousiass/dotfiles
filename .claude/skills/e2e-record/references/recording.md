# 録画の実行手順

## 経路A: playwright codegen（おすすめ・情報量が最大）

### 起動

```bash
bunx playwright codegen \
  --test-id-attribute=data-testid \
  --load-storage=.auth/<role>-0.json \
  --save-har=e2e/_recordings/<name>.har \
  --output=e2e/_recordings/<name>.raw.ts \
  "$E2E_BASE_URL"
```

- `--test-id-attribute=data-testid`: 画面の目印を優先して記録させる。変換精度が段違いに上がる
- `--load-storage`: ログイン済みの状態で始まる。**テスターにログイン操作をさせない**（録画にログインが混ざると毎回のテストが遅くなる）
- `--save-har`: 通信の記録。Law #7 の待機を自動で埋めるのに使う
- `run_in_background: true` で起動し、ブラウザが閉じられて終了通知が来るまで待つ

### テスターへの声かけ（このまま伝える）

> ブラウザが開きます。ログインは済ませてあるので、**確認したい操作をいつも通りやってみてください。**
>
> - ゆっくりで大丈夫です。待ち時間も記録されます
> - 途中で操作を間違えたら、そのままやり直して構いません（あとでこちらで整えます）
> - 別のウィンドウ（記録用の小さい画面）が一緒に出ますが、触らなくて大丈夫です
> - **操作が終わったら、ブラウザを閉じてください。** それで録画が終わります

### 終了後

`e2e/_recordings/<name>.raw.ts` と `.har` ができていることを確認する。
`.raw.ts` が空、または `goto` だけの場合は録画が成立していない。テスターを責めず「うまく記録できなかったので、もう一度お願いできますか」と伝えて再実行する。

## 経路B: Chrome DevTools Recorder

テスターの手元に開発環境が無い、または CLI を触らせたくない場合。

### テスターへの声かけ（このまま伝える）

> 1. Chrome で対象の画面を開き、ログインしておいてください
> 2. `F12`（または右クリック →「検証」）で開発者ツールを開きます
> 3. 上部のタブの `>>` から **「Recorder」** を選びます
> 4. **「Create a new recording」** を押し、名前を付けて **「Start recording」**
> 5. **確認したい操作をいつも通りやってみてください**
> 6. 終わったら **「End recording」** を押します
> 7. 右上のダウンロードアイコンから **「Export as a JSON file」** を選び、保存します
> 8. 保存したファイルの場所を教えてください

受け取った JSON を `e2e/_recordings/<name>.json` に配置する。

### 経路B の制約

- **HAR が無いため通信を待つ処理を自動で埋められない。** ソート・フィルタ・ページングなど「押しても見た目が変わらない」操作が含まれる場合、変換後に手動で `runAndWaitForRpc` を入れる（対象エンドポイントはアプリのコードを読んで特定する）
- 目印（`data-testid`）が無い要素は CSS セレクタや XPath で記録される。変換時にアプリ側へ目印を付与する

## 録画データの取り扱い

**`e2e/_recordings/` は絶対にコミットしない。**

HAR には以下がそのまま入る。

- 認証トークン・セッション Cookie
- API のリクエスト／レスポンス本文（実データ・個人情報を含みうる）

`.gitignore` に以下を必ず入れる。

```gitignore
e2e/_recordings/
.auth/
```

変換とテストの green を確認したら、`e2e/_recordings/` は削除する。デバッグのために残したくなるが、残さない。必要なら録画し直すほうが安全。

## 複数の録画をまとめて処理する場合

テスターが先に何本か録りためているケースもある。`e2e/_recordings/` 内の未変換ファイルを列挙し、**1本ずつ**フェーズ2〜4を回す。まとめて変換して最後にテストすると、どれが落ちたか切り分けられなくなる。
